# Sprint 76 — the switch that decides which mission a class may open

**Date:** 2026-08-29
**Reviewed against:** HEAD `2f2d262`
**Scope:** `setAssignmentAction` only, plus two narrow guard entries. Authored
grades 2–4 practice only; no student free text, new student fields, telemetry,
risk scores or individual administrator surveillance.

## The finding

`setAssignmentAction` called `assignMission`/`unassignMission` and then
`recordAudit` as two separately committed writes. That control decides
immediately which authored mission a class may open: assigning exposes a mission
to children, unassigning withdraws one that may be half-finished. A failing
audit insert left either outcome with no record — and `AssignToggle` received an
uncaught error rather than a state a teacher could act on.

**And the second half of the brief was right.** Both repository calls are
idempotent — `INSERT … ON CONFLICT DO NOTHING`, and a `DELETE` whose change
count was discarded — so a double-tap or a stale tab produced a **"mission
assigned" audit entry for a mission the class already had**. An audit log that
records events which did not happen is worse than one that is merely incomplete.

## The correction

Mission validity, owned-class access and the lapsed-term refusal all stay above
the transaction. The change and its audit are wrapped in `auditedWrite`.

Both repository functions now **return whether a row actually changed**, and
`auditedWrite`'s audit callback may return `null` to mean "the write turned out
to be a no-op, record nothing". The write still runs inside the transaction
either way; only the record is conditional.

**No-op behaviour, defined rather than invented:** assigning a mission the class
already has, or unassigning one it does not, returns **no error** — the class is
in the state the teacher asked for, and the switch should show it — and writes
**no audit entry**, because nothing happened. No new event is fabricated and no
false failure is reported.

On unexpected failure, through the existing `AssignToggle` path:

> That did not save. Room 12 is offered exactly the same missions as before, no
> child's saved mission work or badge has changed, and nothing was written to
> the audit log. It is safe to try again.

`AssignToggle` already rolls the optimistic switch back and renders `result.error`,
so no component change was needed.

Both `assignMission(` and `unassignMission(` join the consequential-write guard;
the expected wrapped-action proof rises to eleven by exactly this action.

## Proof — the child endpoints, not the assignment row

Assignment existence is not the child-facing consequence, so every access state
is exercised through the **real exported `beginMission` / `submitDecision`** as
the signed-in child, with the teacher session restored afterwards.

| Case | Asserted |
| --- | --- |
| **Failed assign** | assignment set, attempts, students, classes and audit all byte-identical; `mission.assigned` count unchanged; **the child still cannot open it** through `beginMission`, and no attempt row exists |
| **Failed unassign** | the mission is still assigned and the snapshot exact; a **half-finished attempt is byte-identical and still continuable** — the child's next `submitDecision` returns `{ ok: true }` |
| **Retry: assign** | assignment set gains exactly that mission; **no attempt created**; exactly one `mission.assigned` audit with the expected detail; **the child can now open it** |
| **Retry: unassign** | mission withdrawn; **the child's work survives** byte-identical; one `mission.unassigned` audit; `beginMission` now refuses |
| **Replay preserved** | withdrawing a mission the child had **finished** still leaves `beginMission` succeeding under the replay rule, badge intact |
| **No-op assign / unassign** | snapshot exact, no audit written, no error returned |
| **Refusals** | unknown mission, cross-owner teacher and lapsed term each write nothing |

One full-suite run failed in `checkin-player` → *"offers Try again, and advances
once the retry succeeds"*: `Unable to find an accessible element with the role
"button" and name "Try again"`. It did not reproduce — 5 clean runs of that file,

sprint 62 fixed one line lower down**.

Sprint 62 changed the *advance* assertion to `findBy` because `confirm` resolves
inside an async `startTransition`. The **rejection** is handled in that same

Now `await screen.findByRole(...)`. Test-only change, no production code, and 8
consecutive runs of that file pass. Reporting it rather than re-running until
green: a gate that passes on the second try has not passed.

## A lifecycle hole found while writing this, and fixed during acceptance

The brief asked for an archived-class refusal test. **There was no such
refusal.** `requireOwnActiveClass` is named "active" but checks ownership and the
subscription term only — it never reads `archived_at` — so a teacher could assign
or withdraw missions on an archived class through the public server action.

**My first assessment of it was wrong, and the reviewer was right to reject it.**
I called it a harmless consistency gap because "an archived class has nobody in
it". That is true only *while* the class is archived. Sprint 69 closes the
student **sessions**; it does not remove the **roster**, the attempts or the
assignments, and the class can be restored. So a mission changed while a cohort
is parked becomes effective for children **the moment somebody restores it** —
with neither the restoring administrator nor the teacher having made a
post-restore decision about that mission. That is a lifecycle consequence, not a
tidiness one, and it also failed the sprint's own stated acceptance criterion.

### The correction

In `setAssignmentAction` only, after mission validity, ownership and the
subscription term, and **before** `auditedWrite`:

```ts
if (classroom.archived_at) {
  return { error: ASSIGNMENT_CLASS_ARCHIVED };
}
```

> That class is archived. Restore it before changing its missions.

`requireOwnActiveClass` is deliberately **not** widened: doing so would change
every classroom mutation at once, which is a different correction. `AssignToggle`
rolls the optimistic switch back on any `result.error`, so this behaves like the
other refusals with no component change.

The regression-pinning test is gone. Four real tests replace it:

| Test | Asserted |
| --- | --- |
| assign refused | the message; **distinct** from `ASSIGNMENT_FAILED` and from the term refusal; full snapshot byte-identical; `join_code` and `archived_at` untouched; zero `mission.assigned` |
| unassign refused | the message; snapshot byte-identical; the mission still assigned; **a child's half-finished attempt byte-identical**; no `mission.unassigned` |
| refused above the transaction | with the audit trigger armed, the result is still the archived message and not `ASSIGNMENT_FAILED` — proving the check runs before any write lock is taken |
| restores cleanly | after `restoreClass`, the same assignment succeeds and writes exactly one audit — the refusal is about the parked state, not a permanent lock |

**Mutation-checked:** removing the refusal fails all four; moving it *inside*
`auditedWrite` also fails all four.

## Known gaps

- **Only `setAssignmentAction` refuses an archived class.** Other classroom
  mutations still go through `requireOwnActiveClass`, which reads ownership and
  the term but not `archived_at`. `renameStudentAction`, `removeStudentAction`
  and `rotateJoinCodeAction` are the ones worth auditing next; each parks
  differently and none was in scope here.
- **Eight configuration actions still audit outside a transaction**:
  `updateSchoolAction`, `requestPlanChangeAction`, `addTeacherAction`,
  `reassignClassAction`, `createClassAction`, `addStudentAction`,
  `renameStudentAction`, `completeCertificationAction`. Four sprints have now
  moved the line; what remains is additive or cosmetic, and `addStudentAction` is
  the closest call left.
- **A no-op returns success**, which is right for the toggle and means a teacher
  cannot distinguish "I changed it" from "it was already so". That is the honest
  trade: the alternative is reporting a failure that did not occur.
- **Failures still write nothing**, consistent with sprints 70–75.
- **The guard reads source text** and would miss a write reached through an alias
  or a helper.
