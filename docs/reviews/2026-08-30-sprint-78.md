# Sprint 78 — a persisted identifier is data, not prose

**Date:** 2026-08-30
**Reviewed against:** HEAD `49363a1`
**Scope:** four `audit_log.action` values, a regression guard, two duplicated
headings, and the withdrawal of an unjustified test-timeout change. No student
data, telemetry, score or new platform scope.

## The finding

The American-English conversion in commit `6c6bfb7` swept four **stored machine
identifiers** along with the product's prose:

| Established key | What 6c6bfb7 made it |
| --- | --- |
| `class.restore_blocked_by_licence` | `..._by_license` |
| `class.restore_blocked_by_licence_config` | `..._by_license_config` |
| `roster.blocked_by_licence` | `..._by_license` |
| `roster.blocked_by_licence_config` | `..._by_license_config` |

These are written into `audit_log.action` in a school's own database. An existing
database keeps the old values while new events use the new ones, splitting one
event type into two spellings with nothing recording why.

I noticed the risk at the time and shipped it anyway, on the reasoning that the
UI does not query by action name. That reasoning was wrong: not querying it
*today* is not a property of the data, it is a property of the current feature
set. An export, a migration, a support query or any later reporting work would
see two taxonomies for one event.

## The correction

All four restored to their established `_licence` spelling — production and
tests, 18 occurrences across five files, plus one code comment that referenced
the wrong form.

**The prose beside them stays American**, which is the whole point of the split:

```
action: "class.restore_blocked_by_licence_config",
detail: `Restoring ${classroom.name} was declined: the school's seat license
         is not a recognized number. Nothing was changed.`,
```

The key is data. The sentence a school reads is prose. No rendered message,
detail, label or error changed, and no part of the broader copy conversion or
the in-memory TypeScript identifier renames was reverted.

## Compatibility: no rows exist in either spelling

Inspected rather than assumed, and **nothing was rewritten**:

- **Schema, migrations, seed** — none of the three references `blocked_by_lic`
  at all, so no migration was needed and none was written.
- **Demo database on disk** — the only action values present are
  `benchmark.opened` ×2, `class.created`, `program.activated`, `report.exported`
  and `retention.updated`. Rows matching `%blocked_by_license%`: **0**. Rows
  matching `%blocked_by_licence%`: **0**.

So no history exists to preserve or to reconcile, and none was touched. Had any
`_license` row existed it would have been left in place and documented as a
mixed-row compatibility note, not deleted.

## Regression coverage

`tests/audit-event-keys.test.ts`, 10 tests. The guard states the rule in its own
header: a stored identifier does not get localized, spell-checked or normalized,
and changing one is a migration rather than an edit.

**Through the real refusal paths**, not source text — because a source assertion
would still pass if the value were rewritten on the way to the database:

| Path | Driven through | Asserts |
| --- | --- | --- |
| Over-license enrollment | `addStudentAction` with a real teacher session | writes `roster.blocked_by_licence`, zero `_license`, detail reads *"An enrollment was declined"*, names no child, roster unchanged |
| Malformed seat license | `addStudentAction` | writes `roster.blocked_by_licence_config`, detail says *"seat license is not a recognized number"*, never echoes the malformed `-7` |
| Over-license restore | `restoreClassAction` with a real admin session | writes `class.restore_blocked_by_licence`, zero `_license` |

The two class keys already had real-path coverage in `audited-writes.test.ts`;
the two roster keys had source-text coverage only, and now have both.

**Mutation-checked one key at a time** — re-normalizing each single `action:`
value independently:

```
re-normalize only roster.blocked_by_licence_config        -> 3 failing tests
re-normalize only roster.blocked_by_licence               -> 3 failing tests
re-normalize only class.restore_blocked_by_licence_config -> 2 failing tests
re-normalize only class.restore_blocked_by_licence        -> 3 failing tests
```

## The test-timeout change from the voice sprint is withdrawn

`49363a1` raised `testTimeout` and `hookTimeout` from Vitest's 5s default to 20s,
on my claim that three intermittent failures were timeouts. **I never saw the
error text.** I inferred "timeout" from their durations (5.0–5.4s), which is
suggestive and is not evidence.

Tested properly this sprint, at the original 5s budget:

- Four consecutive full runs on an idle machine: **all clean.**
- Two full suites run **concurrently**, which is the load present when the
  failures first appeared: **both clean, 846/846 each.**

I could not reproduce it, so the increase is unjustified and is **reverted**.
Keeping a 4× global timeout on an unproven hypothesis is exactly how a real race
gets masked. If the flakiness recurs, the first step is capturing the actual
error text, not widening the budget.

What remains true and unproven either way: `createTestDb` seeds a whole demo
school per fixture and the heaviest test takes ~2.7s idle, so the suite does run
close to the default. That is a reason to make the fixtures cheaper, not a reason
to raise the ceiling.

## Known gaps

- **The rule is a test, not a mechanism.** Nothing stops a future action from
  inventing a fifth key and spelling it however it likes; the guard pins the four
  that exist. A stored-key registry the actions had to draw from would be the
  durable version.
- **No other stored identifier is pinned.** `audit_log.action` carries a dozen
  other values — `class.archived`, `year.dates_set`, `data.deleted` and the rest
  — and none of them is protected from the same kind of sweep. They survived
  that conversion only because they contain no British spelling.
- **The suite runs close to its default timeout.** Unproven as a cause of
  anything, but the fixture cost is real and worth reducing.
