# Sprint 81 — an annual subscription that granted perpetual use

**Date:** 2026-08-30
**Reviewed against:** HEAD `834632d`
**Scope:** read access to the authored curriculum. Six page components gained a
gate, one new resolver, one new panel, one block of copy, one test file. No
schema change, no new field, no data collection, no billing machinery, and not
one line touched in a student-facing path.

**Includes the acceptance correction** that reconciled the plan cards with the
public family route — copy and comments only, no routing change. Recorded here
rather than as a new sprint, and nothing is renumbered.

## The finding

Sprint 49 gave `schools.term_renews_on` a meaning and built `subscription-gate.ts`
to enforce it. That gate refuses classroom **writes** after the term ends, and it
was treated as the whole of enforcement. It was half of one.

Every authored teaching route asked only `requireStaff`. A signed-in teacher at a
school whose term ended a year ago could still open `/teacher/missions`, read
every branch of all 27 missions at `/teacher/missions/[slug]`, print the
discussion guides at `/teacher/guides/[slug]`, run `/teacher/classroom/[slug]` on
a projector, and take the educator orientation. The plans page sells exactly
those things, per year.

**Classroom Mode is the part that makes this more than an oversight.** It records
nothing — no attempt, no evidence, no audit row. No write ever happens, so the
write gate never fires. The product's primary use in front of a class, the one
the marketing copy leads with, ran indefinitely on a single year's fee. An annual
subscription that grants perpetual use of the thing it sells is not an annual
subscription, and the read-only notice in the shell was describing a boundary
that did not exist.

A second, smaller thing fell out of reading these routes: **`/teacher/guides/[slug]`
had no authentication call of its own at all.** It relied entirely on the teacher
layout's `requireStaff` — a redirect in a sibling component rather than a check on
its own data path. It was never exploitable, because a layout redirect does abort
the response, but "the page next door checks" is not what the other eight pages
do and is not what a reader of this file would assume.

## The correction

`src/lib/auth/instruction-access.ts`, one resolver, called first in each of six
page components:

```ts
const gate = await requireOpenCurriculum();
if (!gate.open) return <CurriculumClosed reason={gate.reason} role={gate.user.role} />;
```

It authenticates before it does anything else — a signed-out visitor is
redirected to sign in by `requireStaff` and never learns whether the school
exists, let alone whether it has paid — and only then asks
`instructionClosed(school, now)`, the same rule the write gate uses. Fail-closed
on both non-active states, including a staff row whose school record cannot be
found at all: no school record is no evidence of a paid term.

It returns a discriminated result rather than redirecting, so the page keeps its
own URL. A teacher whose administrator renews, or whose account team corrects the
dates, reloads the page they were already on and is teaching again. Recovery was
driven in the browser and needs no restart, no reseed and no cache clear.

### What is gated, and what is deliberately not

| Gated | Open |
| --- | --- |
| `/teacher/missions` | `/teacher` — the school's own classes and history |
| `/teacher/missions/[slug]` | `/teacher/class/[classId]` — roster, history, evidence |
| `/teacher/guides/[slug]` | `/teacher/certification/certificate` — already earned |
| `/teacher/classroom/[slug]` | every `/admin` route: reports, exports, retention, deletion, staff administration |
| `/teacher/certification` | sign-out |
| `/teacher/how-to-run-a-session` | |

**The boundary is ownership, not leverage.** What is gated is the authored
curriculum, which is the vendor's and is licensed by the year. What is not gated
is everything the school produced or earned. Renewal is never a condition for a
school to reach its own records, and both refusal messages say so in those words.

`/teacher/how-to-run-a-session` is not in the finding's list and is gated anyway:
it is authored pedagogical content of exactly the same kind, and the inventory
test below would have forced the decision regardless.

`/teacher/certification/certificate` is deliberately open. A completion
certificate is the reader's, not the vendor's, and taking it back at renewal time
would be the hostage-taking the rest of this sprint is built to avoid. The
orientation modules are gated; the certificate for having finished them is not.

### Two states, two claims, never borrowed

`lapsed` says a term ended and offers renewal. `needs-configuration` says
outright *"This is not an expiry: nothing has ended and nothing is overdue"* and
asks for the dates to be corrected. Telling a school its subscription expired
when the truth is that somebody typed `"soon"` into a date field is a false
commercial claim, and it is the kind that costs a renewal conversation.

Recovery is role-appropriate for the reason sprint 59 established: only an
administrator can open `/admin/program`, so a teacher is given a person rather
than a link that would bounce them. A route back to the reader's own dashboard is
always present and always last, because a dead end here would read as a lockout
of the school's own data.

Child-facing copy is untouched. Children are already blocked at the class and are
never shown billing language; a test asserts neither string can reach the mission
player.

## Family take-homes: resolved, not deferred

The first pass gated the curriculum and left `/family/[slug]` public, which was
the right call about the route and only half an answer. It left the Single
classroom plan card still selling **"Printable family take-homes"** by the year
while the product prerendered those pages for anyone with the link. A buyer
reading that card and then finding the pages open would be right to ask what
else on the list is not what it says.

**The contradiction was resolved on the commercial claim, not on the page.**
Privatizing the caregiver pages to justify a bullet would have made the product
worse in exactly the direction it has always refused: a session check there would
collect a reader nobody collects today, cost 33 pages their static rendering, and
stop a caregiver holding a photocopy — all to enforce a boundary that a private
browsing window defeats.

What changed:

| Surface | Before | After |
| --- | --- | --- |
| Plans, Single classroom | `"Printable family take-homes"` as a paid feature | removed |
| Plans | — | a section, **"Free for families, subscription or not"**, naming them a *free public resource*, *not part of any plan*, needing *no subscription*, readable whether or not the school's term is current |
| For your school, Teachers | "a printable discussion guide **and a family take-home** for every mission" | "a printable discussion guide for every mission, and a family take-home that goes home **free either way**" |
| For your school, Families | "nothing to sign up for" | "nothing to sign up for **and nothing to buy**", plus "Free public resources, not part of any plan… no subscription is needed" |
| `CURRICULUM_SCOPE` | already excluded them | now **exported**, so a test can hold it that way |
| `subscription.ts`, `instruction-access.ts`, `family/[slug]` | comments describing take-homes as sold per year | corrected, with the reasoning for the split recorded where each decision lives |

The curriculum gate is unchanged: the mission library, mission detail, printable
discussion guides, Classroom Mode, the orientation and the how-to-run guide stay
gated exactly as this sprint first implemented them.

`/family/[slug]` is unchanged too, and that is the point — still
`generateStaticParams` over every session and mission, still 33 prerendered
pages, still no session, no `requireStaff`, no cookie read, no form and no server
action.

### The test couples the two halves

Six tests, so that neither the copy nor the route can move on its own:

- no plan's `features` — or its `planned` list, which would be the same claim
  deferred — mentions a family take-home
- the plans page says *free public resource*, *not part of any plan*, *no
  subscription*
- `CURRICULUM_SCOPE`, the sentence a blocked teacher actually reads, does not
  name them and still names the discussion guides
- only the Families card claims them as free; any other card that mentions one
  must qualify it as free, either way, or without a subscription
- the family route takes no session: no `require*`, no session import, no
  `cookies(`, no form, input or `"use server"`
- it stays statically generated over `ALL_SESSIONS`, with no `force-dynamic` or
  `revalidate = 0`

Two mechanisms make those assertions mean something:

- **The tree is rendered.** A page returning `<CurriculumClosed …/>` returns an

  find two props and none of the copy, and would pass just as happily if the page

- **Props are read, not just children.** `ClassroomPage` returns

## Known gaps

- **The free/paid split now lives in prose, held by a test.** Nothing structural
  distinguishes a free public page from a licensed one; `OPEN_BY_DESIGN` and the
  plan-card assertions are conventions the tests enforce. A route-level marker
  the plan cards were generated from would make the two impossible to separate,
  and is a larger change than this.
- **The gate is per-page, six times over.** Same shape as the `archived_at`
  checks sprints 76 and 79 added one at a time, and the same objection applies: an
  intent-aware resolver — reads of vendor content, reads of school records,
  writes — would be the durable thing. The inventory test is what stands in for it,
  and a test is not a mechanism.
- **The inventory only walks `/teacher`.** A new authored teaching route under a
  different prefix would not be enumerated. `/admin` is exempt wholesale on the
  reasoning that it holds no curriculum, which is true today and is an assumption,
  not an invariant.
- **The gate reads a date, and nothing verifies that date is real.** This
  enforces `term_renews_on` faithfully. Nothing stops that column being edited in
  the database, which is correct for a demo build and is not an entitlement system.
- **Nothing gates the API surface, because there isn't one.** If a JSON route ever
  serves mission content, it inherits none of this.
