# Sprint 49 — the term that ended and changed nothing

**Date:** 2026-08-28
**Scope:** one state transition. A lapsed subscription makes instruction
read-only. No billing, no integration, no schema change, no deletion.

## The finding

The product sells an annual subscription and stores `term_renews_on`. Until now
that date changed labels and nothing else: every classroom and student write
succeeded after it. The Program & plan page said so out loud — it described a
real deployment making classes read-only and then admitted *"Nothing switches
off automatically in this build."*

So a school could teach indefinitely on an expired term. Sprints 42 and 43 made
the seat count the vendor's number and enforced it; the term itself was still a
note in a diary. An entitlement that never ends is not an entitlement, and a
renewal date nothing depends on is not a renewal date.

## The rule

One file, `src/lib/domain/subscription.ts`, decides. It matches the wording the
product already used: **the school is active through the renewal date and lapsed
on the next calendar day.** A renewal on 2026-09-01 makes the first of September
a normal teaching day.

**Date-only, deliberately.** The stored value is `YYYY-MM-DD` — a school
business date, not an instant — so the comparison is between date strings, never
timestamps. `now` is injected everywhere and reduced to its **UTC** calendar
date rather than the server's local one, because a deployment that lapses at a
different moment depending on the host's `TZ` is a bug nobody can reproduce. The
cost is that the boundary can sit a few hours off a school's local midnight; the
benefit is that it is the same everywhere. The existing `rollover.ts` already
uses UTC date parts for the same reason.

**An empty renewal date never lapses a school.** Refusing to teach because a
field is blank would be the software inventing a commercial fact.

## Enforcement

`src/lib/auth/subscription-gate.ts` sits on the path every instructional
mutation already takes, not in the pages that render the buttons — the same
reasoning as sprint 26 for authorization and sprint 42 for the seat cap. A stale
tab left open over the summer, or a direct call to an exported server action,
cannot write.

It is attached to the **shared resolvers**, so it is one door rather than
sixteen remembered checks:

- `requirePlayableMission` and `requireOpenCheckIn` — every student write goes
  through one of the two.
- `requireOwnActiveClass` (teacher) and `ownActiveClass` (admin) — ownership
  first, then the term. Both are separate questions: a teacher's own class is
  still their own class after the term ends, and they still cannot change it.

**Blocked:** starting/resuming and recording mission progress, check-in answers
and completion, joining through a class code, class creation and lifecycle,
roster changes, code rotation, assignment changes, check-in windows, and
year rollover.

**Open, deliberately:** read-only staff and admin pages, the annual report and
all three exports, the quote/renewal request, sign-out, school contact and
profile, staff administration, retention settings, the academic-year dates that
retention is calculated from, deliberate deletion, and the educator orientation
— which touches no classroom or child record. **A school still owns its
records**, and holding them hostage to an invoice would be the wrong product.

**Expected errors, not crashes.** The gate throws, because a throw is what a
shared resolver can do without every caller remembering to check. The actions
that render a result catch it and return `{ error }`; anything else still throws,
which is the backstop. Seven actions changed return type from `void` to
`{ error?: string }`, and their three callers now surface the message —
including `AssignToggle`, which also **puts its optimistic switch back**, since a
toggle that stays flipped after a refusal tells a teacher a mission is assigned
when it is not.

## What people see

**Staff** get one notice in the shared shell, so it cannot be missed by landing
on a page that happens not to carry it. `role="status"`, not `alert`: it is a
standing condition, not an emergency interrupting what they are doing. It says
the subscription ended, that classroom changes are paused, that records, reports
and exports remain, that nothing has been deleted, and links to the renewal
request.

**Children** get *"Your class isn't open right now. Ask your teacher."* and
nothing else. A child is not a party to the contract and is never shown billing
language. Their session, badges, map and every finished mission stay exactly as
they were.

**No control lies.** When the class is closed the student home does not offer
"Up next" or the check-in, and the mission tiles render as tiles rather than
links — a card that looks tappable and then refuses is worse than one that
plainly is not. The false admission on Program & plan is replaced by a
description of what actually happens.

## Tests

`tests/subscription-lapse.test.ts`, thirteen cases, no clock: every date is
injected.

- **The rule**: active on 31 Aug and on the renewal day itself, lapsed on 2 Sep;
  23:59:59 on the boundary is active and 00:00:00 the next day is not; an empty
  renewal date never lapses.
- **The gate**: refuses after the term, allows on the boundary day and after
  renewal, measures each school against its own term.
- **Zero writes on refusal** — the whole database is snapshotted table by table
  and compared after two refused attempts. No audit row, no flag, no counter: a
  refusal is not an event about a child and is not recorded as one.
- **Nothing lost**: roster, attempts, check-ins and school all still readable.
- **Voices**: the child message contains none of *subscription, renew, invoice,
  pay, licence, $*; the staff refusal names what remains and where to renew.
- **The action inventory.** Every exported server action across all four action
  files must appear in either the gated map or the allowed map, each with a
  written reason, and the test fails on an unclassified action **and** on a
  classified one that no longer exists. It then checks each gated action's body
  actually reaches a guard, and that the allowed ones do not. **A new mutation
  cannot silently bypass the gate — it has to be decided about.**

Two existing tests asserted the ownership resolvers by literal name; they now
accept the gated variants **and additionally assert that the gated variant
delegates to the ownership one**, so the looser regex cannot be satisfied by a
helper that skipped the check.

**566 tests, up from 553.**

## Verified in the browser

With the demo school's renewal date moved into the past, at **1280×800** and
**768×1024**:

- Teacher overview and admin pages show the notice with a working renewal link;
  no overflow at either size.
- Rotating a class code returned **the expected refusal**, not an error page; the
  code was unchanged in the database and **no audit row was written**.
- Archiving a class at tablet width refused the same way, class still active,
  focus still visible.
- A **correct** class code at `/join` was refused with the child's sentence.
- A student session opened before the lapse **kept working**: still signed in,
  16 badges, every finished mission readable, zero links into the player, and
  tiles reading *"Not open right now"*.
- The annual report rendered with **Print, Download CSV and Download JSON** all
  present, and the **renewal request succeeded**.
- The *"Nothing switches off automatically"* admission is gone.

Demo data restored afterwards: renewal 2026-09-01, four active classes.

## Preserved

Authored grades 2–4 decision practice, no open chatbot, no child free text, no
new student fields, no behavioural telemetry, no risk scoring, aggregate-only
administrator reporting. No schema change: `term_renews_on` already existed and
now means something.

## Observed, not built

- **No grace period or warning before the date.** The transition is a cliff on
  one morning. A real deployment would want "renews in 14 days" escalating in
  the shell, and that is a product decision about tone rather than a mechanism.
- **Nothing reconciles the term against an actual agreement** — still true from
  sprint 42. Renewal is a vendor edit to the row.
- **A lapsed school's teachers can still open Classroom Mode**, which records
  nothing by design, so it is not a write. That is arguably correct — it is
  teaching from a plan the school already bought — but it is a judgement call
  worth a second opinion.

## The lesson

**A field nothing reads is a field that means nothing, and a promise the code
does not keep is worse than one it never made.** The Program & plan page was
honest about the gap, which is better than hiding it — and an admission in the
interface is not a substitute for the behaviour. The gap was documented for
three sprints in `LATEST.md` as "lapsed-subscription enforcement remains
documented and unbuilt", which is exactly how a known absence becomes furniture.

# Sprint 50 — the correction

Independent review rejected sprint 49 on two acceptance misses. Both were mine,
and the first is the one worth dwelling on.

## 1. The second half of joining bypassed the gate

`findClassByCode` checked the term. `chooseStudent` did not — and I had
classified it in my own inventory as **"resumes an existing session; recording
is gated separately."** It does not resume a session. **It creates one**, from a
join grant that lasts ten minutes.

So: a child types a correct code at 9:59, the school lapses at 10:00, the grant
is still valid, `/join/[classId]` still renders the whole roster by name, and
pressing a name cleared the grant and wrote a fresh student session without
asking about the term again.

**Checking the first step of a two-step flow is checking half of it.** And the
inventory test that existed precisely to stop this was satisfied — because the
thing it checks is a sentence I wrote, and the sentence was wrong. A guard whose
correctness depends on a description being accurate is only as good as the
description.

**Fixed:**

- `chooseStudent` is **gated**, reclassified with what it actually does.
- The term is rechecked **after** the grant, class and code are validated — so a
  refusal cannot leak that a class exists — and **before** any session write. A
  test asserts that ordering by index, not just that the call is present.
- `/join/[classId]` checks the term **before reading the roster**, not merely
  before rendering it: a closed class should not be handing out a class list.
- On refusal both paths **clear the join grant**, so a refused child is not left
  holding a credential that would let them retry the stale page, and redirect to
  `/join?closed=1`, which shows the same child-safe sentence. **No session, no
  audit row, no record that a child tried** — and the failed attempt is not fed
  to the code throttle either, because it was not a wrong guess.

## 2. Lapsed Restore crashed instead of refusing

`restoreClassAction` resolved the class with `ownActiveClass` **before** its try
block, so `SubscriptionLapsedError` escaped as an unhandled throw and an error
page. Archive and rotate, which I had wrapped whole, returned the sentence.

The cause is exactly the mechanical one it looks like: those two were rewritten
by wrapping the entire body, and this one already had a try block for the
licence refusal, so the resolver stayed above it. **A guard that turns one
refusal into a crash is not a guard the caller can use**, and three actions
behind the same button pattern have to fail the same way.

**Fixed:** the resolver is inside an encompassing try, the existing
`RestoreExceedsLicenceError` handling is preserved unchanged inside it, and
`asExpectedError` converts the lapse. A test asserts the try opens *before* the
resolver in all three actions, so the next one cannot drift.

## Coverage

Eight cases added, twenty-one in the file. **Seven confirmed to fail against the
sprint-49 code** — including `routes every gated action through the gate`, which
now fails for `chooseStudent`, which is what it should have done all along.

One of the new assertions tripped on its own first draft by matching the import
path `domain/subscription` and my own comment containing "renew". Sprint 44's
lesson, re-learned: comments and imports are not copy, and a scan for
child-facing language has to strip them first.

## Verified in the browser

**The stale grant, end to end at 1280×800.** Entered a correct code while
active → roster with 23 names. Lapsed the school with that page still open.
Pressed a name: landed on `/join?closed=1` with *"Your class isn't open right
now. Ask your teacher."* Then `/student` redirected to `/join` — **no session
was written** — and `/join/cls_room12` redirected too, with **zero names
rendered**.

**Lapsed Restore at 1280×800 and 768×1024.** No crash, the refusal announced in
the row, class still archived, focus still visible, **audit count unchanged at
16 before and after**, and no horizontal overflow at either size.

Demo data restored: renewal 2026-09-01, four active classes, 16 audit rows.

**574 tests, up from 566.**

## The lesson

**An inventory is only as good as the descriptions in it.** I built the guard
that was meant to make this impossible, and then defeated it in the same commit
by writing "resumes an existing session" about an action that creates one. The
test could not know better; it compared my list against the code and found the
action classified, which was all it was ever able to do.

Where a classification carries the safety property, the description has to be
checked against the behaviour rather than against the name — and for a
multi-step flow, every step needs its own answer, because the gate belongs at
the write and not at the entrance.
