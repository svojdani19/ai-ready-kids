# Sprint 68 — rotation invalidated the way in, not the people already inside

**Date:** 2026-08-29
**Reviewed against:** HEAD `53a5d6e`
**Scope:** bind a student session to the code that issued it, and align every
rotation claim. No database field, no student data field, no telemetry, no risk
scoring, no free text, no broader auth platform.

## The defect

Rotation is the recovery action the product recommends by name. Sprint 66 made
that recommendation more prominent, on the reasoning that a code read aloud to a
room will travel and rotation is the answer when it does.

It was half an answer.

| Credential | Before rotation | After rotation |
| --- | --- | --- |
| A new join with the old code | works | **rejected** — `getClassByJoinCode` no longer matches it |
| A half-finished join grant | works | **rejected** — the grant carries the code, and `/join/[classId]` and `chooseStudent` both re-check it |
| **A student session already issued** | works | **still works** |

The session was `{ kind: "student", studentId }`. It recorded *who* was signed
in and nothing about *how they got in*, so `currentStudent` had nothing to
compare against the class's current code — it loaded the student, loaded the
class, and returned both. A browser that entered through a leaked code stayed
inside the class for the rest of the twelve-hour session lifetime, after the
administrator had done exactly what the product told them to do.

Meanwhile three surfaces and two audit entries said *"the old code stops working
immediately"*.

## The correction

**One field, in the cookie, nowhere else.**

`SessionValue` for a student is now
`{ kind: "student"; studentId: string; code: string }` — the normalised join
code, which is the same marker the join grant already carried. It is not
persisted: it lives inside the signed HttpOnly cookie, no screen renders it, and
no column was added.

- **`chooseStudent`** issues the session with `grant.code` — the code the
  verified grant carries, which the checks immediately above it have just
  confirmed is still the class's current one. It is not re-read from the class:
  a session should record what authorised it.
- **`enterDemo("student")`** reads the demo student's class and issues against
  its current code, so a demo session is no more privileged than a real one.
- **`currentStudent`** compares `normaliseJoinCode(classroom.join_code)` with
  `normaliseJoinCode(session.code)` and returns `null` on mismatch. Both sides
  are normalised so a stored code that was never normalised cannot fail to match
  itself. Archive and entitlement checks are untouched, as is the twelve-hour
  maximum lifetime.
- **`currentStaff`** is unchanged. A teacher's session has nothing to do with a
  class code, and rotating a code must not sign out the person rotating it.

**Legacy tokens fail closed.** `decodeSession` requires a non-empty `code` on a
student token. A token from an older build has none and decodes to `null`.
Treating a missing binding as "matches any code" would have preserved the exact
hole being closed. The one-time consequence, stated rather than smoothed over:
**student sessions issued before this commit are rejected, and those children
are asked to rejoin once.** There is no seamless migration and none is claimed.

## What rotation still cannot do

A page already rendered on a screen stays rendered. Nothing in this build pushes
to a connected browser, so a child mid-mission keeps that screen until they
navigate — at which point the next request is rejected. The copy now says this
rather than implying real-time control:

> From then on the old code is rejected on the next request that uses it:
> nobody can join with it, a half-finished join stops, and a browser already
> signed in with it is asked to rejoin the next time it loads a page. …
> What rotation cannot do is reach into a page already on a screen.

Aligned in five places: `CLASS_CODE_BOUNDARY` (rendered on `/privacy` and the
home page), the admin Classes note, both `class.code_rotated` audit details
(admin and teacher actions), and the README's access-control section — which now
also records the binding, the comparison point and the legacy-token consequence.

## Remaining production gaps

- **No revocation of a rendered page.** Containment is per request. A deployment
  that needed a child's screen to clear on rotation would need a push channel,
  which this build does not have and which the copy no longer implies.
- **The binding is a code, not a version counter.** Rotating a code twice back to
  the same value — vanishingly unlikely with this generator, but not impossible
  — would revalidate an old session. A monotonic per-class version column would
  close that, and is a database field, which this sprint was told not to add.
- **Sessions still last twelve hours** and are still the only student credential.
  Rotation now bounds a leak to "until the next request", which is a real
  improvement and is not the same as short-lived sessions or SSO.
- **The one-time rejoin is real.** Anyone with a student session from before this
  commit is signed out. In a local demonstration that costs nothing; in a
  deployment it would need saying to teachers in advance.
