# Sprint 02 review — 26 August 2026

**Scope.** Two findings raised from independent browser testing of the Sprint 01
deliverables: branch comparison on a touch-only board in Classroom Mode, and
save-before-advance resilience in the student players.

**Method.** Ran against the checklist in `../classroom-review.md`. Group review
in Classroom Mode at 1280×800, driven **by tap only** for the branch switcher
rather than by keyboard. Independent review of the check-in and the mission
player at 768×1024, with the network genuinely broken mid-flow (`window.fetch`
replaced with a rejecting stub) and the database inspected after each step to
confirm what was and was not written.

---

## Findings and what changed

### 1. Revealing a branch removed the only touch route to the others — fixed

Tapping a choice replaced the choice list with that branch's feedback. Number
keys could switch branches, which is fine at a laptop and useless on an
interactive whiteboard with no keyboard: the only way to reach B or C was to
advance past the decision and come back, losing the thread of the discussion in
front of the class.

**Added a branch switcher** that stays on screen while feedback is open: one
control per branch showing its letter and label, plus *Show the choices* to
return to the list. It is deliberately distinct from the hands-up tally in the
facilitation bar — different position, different styling, different verbs. One
changes what the room is looking at; the other counts votes. Confirming that
they cannot be confused is now a test.

Supporting changes:

- Revealing became **set** rather than **toggle**. With a persistent switcher,
  a toggle would make tapping the active button behave differently from tapping
  its neighbours, which is exactly the sort of inconsistency that trips someone
  up in front of a class.
- **Escape** returns to the choice list, and the plan screen's key reference
  documents it.
- The **question stays on the board** while a branch is open, so the room can
  still see what is being answered.
- Every branch control is `min-h-12` (48px) — a board is tapped with a whole
  finger, often at arm's length.
- Choice-list buttons gained the same explicit naming as the switcher
  (*"Show what choice B does: …"*), so a screen reader announces the action
  rather than only the option text.

### 2. The check-in advanced before the answer was saved — fixed

The worst class of bug this product can have. `confirm()` started the save and
advanced in the same tick, so on a dropped school network the child landed on
the next story while an error message described an answer they could no longer
see — and that answer was simply gone. Assessment data that disappears quietly
is worse than assessment data that fails loudly, because nobody can tell it
happened.

**Next now waits for the server.** While saving, the button reads *Saving…* and
is disabled, Back is disabled, and the status line says so calmly. On failure
the child stays on the same story with their pick still highlighted, sees
*"Your pick is still here. Tap Try again when you are ready."*, and the button
becomes **Try again**. Only a successful save advances. Choosing a different
option clears the error.

Verified end to end: with `fetch` broken, the database held zero rows for that
student; after restoring the network and tapping Try again, it held exactly one
answer and the child moved to story 2. No duplicate from the failed attempt.

### 3. The same gap in the mission player — fixed

Applied the same principle to decisions. The authored feedback still appears
**instantly**, because it is local content and making a child wait to read it
would be pointless cruelty. What waits is the way forward: *Keep going* is
replaced by a disabled *Saving…* until the decision is recorded, and by a calm
*Try again* if it fails, with the feedback still on screen and the message
*"Nothing is lost — your answer is still right here."*

This covers loop-back branches too, so an unsafe choice is recorded before the
child returns to the question. Completing a mission got the same treatment: if
`finishMission` fails, the ending screen offers a retry rather than silently
dropping the badge.

**Replays remain write-free.** A finished mission records nothing, so there is
nothing to wait for and the button is enabled immediately — asserted by test.

## Checked and found acceptable

- **Touch-only group flow.** Verified by tapping at rendered coordinates, not
  by ref or keyboard: C → B switched branches, `aria-pressed` moved, and the
  scene did not change. *Show the choices* returned to the list.
- **Distinct meanings preserved.** Tapping the hands-up tally while a branch is
  open does not change which branch the room is reading.
- **Nothing recorded in Classroom Mode.** Still true after this sprint; the
  component imports no server action at all.
- **No new data.** Neither fix adds a field, a table, a log or a timing. The
  failure path stores nothing anywhere, including locally.
- **Calm under failure.** No red X, no alarm, no blame. Both error messages
  tell the child their work is safe and what to tap next.
- **Accessibility.** Branch controls carry names that state their effect;
  errors are `role="alert"`; the check-in status line is `role="status"`;
  keyboard routes (numbers, Escape, Tab, Enter) all still work.
- **Teacher workload.** Unchanged; the switcher removes work rather than adding
  it.

---

## Deliberately left

- **No retry backoff or offline queue.** A single explicit retry is the right
  amount of machinery for a local MVP, and an automatic background queue would
  reintroduce exactly the silence this sprint removed. A district deployment on
  flaky wifi should revisit this with a visible queue, not an invisible one.
- **Switcher labels truncate to about 22 characters.** The letter badge carries
  identity and the full text sits in the accessible name and in the panel
  below. Wrapping full labels would push the feedback off a 720p board.
- **No presenter-side "what did the room pick" record.** Tempting, and still
  the wrong trade: it would turn a group discussion into data about children.
