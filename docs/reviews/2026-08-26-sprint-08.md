# Sprint 08 review — 26 August 2026

**Scope.** Turn the marketing site into a real landing page with the depth
behind header menus, and brighten the palette for a grades 2–4 audience.

**Method.** Ran against the checklist in `../classroom-review.md`. Palette
checked as a full pair matrix before a single component used it. Dropdown
behaviour driven in a live browser at 1280×800; student surfaces re-checked at
768×1024 after the recolour.

---

## What changed

### The landing page now does one job

`/` was a single scrolling page carrying eight sections behind anchor links.
An evaluator arriving for one specific thing — usually privacy or price — had
to scroll past four others to reach it. The page is now a hero, a three-
competency signpost, one honest-claim panel and a closing call to action.

Everything else became a real page with its own URL, title and description:
`/approach`, `/curriculum`, `/benchmark`, `/for-schools`, `/plans`, `/demo`.
`/privacy` already existed and joined them. All seven sit in a `(site)` route
group with shared header and footer.

Moving the demo cards to `/demo` had a side benefit: `/` no longer reads the
database, so it is statically rendered again.

### Header menus

Two disclosure menus — *The program* and *For your school* — plus direct links.
Deliberately **not** an ARIA menubar: a menubar hijacks the arrow keys, and
this is a set of links, not a command surface. A button that expands a list of
links is what a screen reader user expects on a marketing site. Escape closes,
a click outside closes, and every item is a plain link that survives JavaScript
failing to load. A separate panel handles small screens.

### Brighter palette

Every hue moved up in saturation, a fourth (grape) was added for the marketing
site so the three competency colours stay unambiguous, and the paper warmed.
The `-deep` tokens remain text colours and the bright tokens remain fills.

Checked as a matrix, not by eye: ink, ink-soft and ink-faint against all nine
backgrounds; white on all five deep tokens; each deep token on its own wash;
and ink on every bright fill. **All pass 4.5:1.**

## Findings during the review

### 1. `Tag tone="grape"` rendered an undefined class — fixed

The new grape hue was added to the theme and used on the landing page before
the `Tag` tone map knew about it, so the class string interpolated to
`undefined` and the tag rendered unstyled. Caught by grepping the rendered
HTML of all seven pages for `class="...undefined`, which is now zero across
every page. A typed tone union would have caught this at compile time; the map
is `Record<string, string>`, which will not.

### 2. The menu closed itself on any window blur — fixed

The dismissal handler closed the menu whenever focus moved outside the wrapper,
including to `document.body`. Focus lands on the body when the window loses and
regains focus, when something resets focus programmatically, and in automation
— so the menu shut by itself. It now ignores focus landing on the body and
closes only when focus moves to a real element elsewhere.

Worth recording how this was found, because it nearly was not: the first tool I
used to test it could not await promises, so each check ran in a fresh context
and reported the menu closed. That looked exactly like a component bug. Driving
it in a browser that could hold state across a delay showed the menu staying
open — and separately surfaced the real body-focus defect. A test harness that
cannot observe a thing correctly will happily report it broken.

## Checked and found acceptable

- **Contrast.** Full pair matrix at 4.5:1, computed rather than judged.
- **Touch targets.** Every header control is `min-h-11`; the small-screen
  toggle is 44×44.
- **Student surfaces after the recolour.** Mission map and mission player at
  768×1024: brighter, still legible, tone semantics unchanged — green still
  means finished, denim still means selected, berry still means attention.
- **No student-facing copy changed.** This sprint touched presentation only.
  No mission, no feedback, no benchmark item, no evidence rule.
- **Standing constraints intact.** No generative model, no free text from
  children, no new student fields, no telemetry, aggregates only for
  administrators.

---

## Deliberately left

- **Adult dashboards inherit the brighter palette.** The original brief asked
  for dashboards that feel calm and credible to an administrator, and brighter
  accents pull against that. Structure carries the credibility instead —
  hairline borders, whitespace, tabular numerals — but if a district contact
  ever calls the reporting screens toylike, this is the trade that caused it.
- **`Tag` tones stay a string-keyed record.** Making it a typed union would
  prevent a repeat of finding 1, but it touches every call site and this sprint
  was already broad.
- **No automated test for the dropdowns.** Their behaviour is browser-verified,
  not asserted. Worth a component test covering open, Escape, outside click and
  the body-focus case before this code is next changed.
