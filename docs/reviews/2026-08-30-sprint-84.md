# Sprint 84 — a parked class that looked open for business

**Date:** 2026-08-30
**Reviewed against:** HEAD `41b8603`
**Scope:** the teacher class page's archived state, plus the acceptance
correction that made it reachable. Two pages branched on `archived_at`, one new
component, one new repository query, one test file. No schema, no field, no
telemetry, no parent surface, no administrator route to an individual child, and
no change to the server-side resolver.

## The finding

Sprint 82 closed all five classroom mutations on an archived class, server-side,
above every transaction, with a refusal sentence per operation. That was correct
and it was half a workflow. `/teacher/class/[classId]` went on rendering a parked
class as if it were live:

- the header showed the join code and a **New code** button
- the assignment panel said a mission "appears on every student's map in this
  class straight away"
- every assignment toggle was live
- **Add student**, **Rename** and **Remove** were all sitting there
- nothing anywhere said the class was archived

The only way to discover the state was to try something and be refused. Sprint 82
recorded this as its top known gap; this is it.

**The classroom cost is specific.** A covering teacher or a substitute reads the
code off this page and writes it on the board, and twenty-three children type a
code that cannot admit them — because archiving rotates it, so it is not merely
stale, it is dead. Somebody promises a class a mission is on. Somebody meets five
refusals in a row standing in front of seven-to-ten-year-olds. For a school
buyer, the server guard is necessary and the visible workflow still looks broken,
which is a support call about a product that is working exactly as designed.

## The correction

One boolean, read once:

```ts
const archived = Boolean(classroom.archived_at);
```

**The page stays fully readable.** No redirect, no 404, nothing hidden that the
teacher owns. The roster, every child's completed missions, the competency
evidence, the cohort figures and the check-in numbers all render exactly as
before — for the same reason sprint 81 refused to gate a school's own records:
archiving parks a class, it does not take its history away.

**The state is stated first.** `ArchivedClassNotice` sits immediately under the
page header, before the panels it explains, and answers the three questions a
teacher has in the order they have them: students cannot join and the code admits
nobody, so it is not worth writing on the board; everything already here stays
readable and nothing has been deleted; and an administrator has to restore the
class before anything can change.

**The code is not presented as usable.** The stored value is deliberately not
printed at all — a code on this page is a code somebody writes on a board — and
is replaced by "Class code · **Inactive** · No code admits students to an
archived class. Restoring the class issues a working one."

**Every mutation affordance is gone, not disabled.**

| Control | Archived |
| --- | --- |
| New code (`ConfirmAction`) | replaced by the inactive-code panel |
| Assignment toggle (`AssignToggle`) | a static `Was assigned` / `Not assigned` tag |
| Add student (`AddStudentForm`) | the whole panel section is not rendered |
| Rename (`RenameStudentForm`) | replaced by a `Read-only` cell |
| Remove (`RemoveStudentButton`) | same cell |

The assignment toggle is the one that became a fact rather than disappearing: a
teacher reviewing a parked cohort wants to know what it was assigned, and that is
information. It renders as a tag with nothing focusable and nothing to press.

**The panel description changes with the state**, because "appears on every
student's map straight away" is false for a class nobody can open: archived reads
*"What this class was assigned when it was archived. Nothing can be turned on or
off until an administrator restores it."* Active wording is untouched.

**Sprint 82's resolver is untouched and still needed.** A tab rendered before the
class was archived still holds every control, so the server refusal is the thing
that actually stops the write. This sprint stops a teacher being sent to it.

## Acceptance correction: the page was honest, and unreachable

The review above shipped with a "known gap" claiming `/teacher` *"still lists an
archived class like any other"*. That is the opposite of what the code does, and
I wrote it without reading the query:

```ts
// listClassesForTeacher
WHERE teacher_id = ? AND school_id = ? AND archived_at IS NULL
```

So the real defect was worse than the one I invented. Archiving a class removed
it from the dashboard, and the dashboard is the **only** navigation to
`/teacher/class/[classId]`. Sprint 84 made that page honest and read-only when
reached; nothing led there. The owning teacher could see the roster, the
completed work and the evidence only from a URL they had bookmarked or guessed —
and a school cannot train a substitute or a returning teacher around a memorised
URL. The acceptance claim that historical records "remain available" was true of
the page and false of the product.

### An archived-only query, not a flag on the active one

```ts
listArchivedClassesForTeacher(db, teacherId, schoolId)  //  archived_at IS NOT NULL
```

Deliberately a second function rather than an `includeArchived` parameter.
`listClassesForTeacher`'s active-only filter is relied on by the dashboard's
counts, the seat usage and the mission library's per-class assignment pickers; a
boolean parameter would have put a parked cohort one wrong argument away from all
of them. This one cannot return an active class, and a caller that wants both has
to ask twice and keep them apart. Every existing caller is untouched.

### The section

An **Archived classes** list at the bottom of `/teacher`, its own
`aria-labelledby` region with an `h2`, holding only what the brief allows: name,
`Read-only` tag, grade, school year, roster count, and **View records** linking
to the sprint 84 page. No join code — archiving rotated it and it admits nobody,
and a code on a dashboard is a code somebody writes on a board. No `Open class`,
no mutation control of any kind.

Counted in nothing. Classes, Students and Assigned-work-completed all stay
active-only, and a test reads the `Stat` **props** rather than the prose, so a
number appearing in a sentence cannot be mistaken for a figure.

### One thing the browser found that the brief did not ask for

With Room 12 archived, the dashboard read *"You do not have a class yet"*
directly above a list of that teacher's own finished cohort. Wrong, and dismissive
of a year they ran. The empty state now says *"You do not have an active class
right now"* and points at the section below it, when and only when there are
archived classes to point at.

## Second acceptance correction: the empty roster still spoke as if active

**Verified before implementing, because the finding turns on a state being
reachable.** Nothing requires a roster to archive a class: `archiveClass` reads
only `archived_at` before writing, and `archiveClassAction` checks only ownership
and the subscription term. Neither counts students. A class created and parked
before enrollment — or emptied and then archived — reaches
`students.length === 0 && archived`, and a test now creates exactly that class
and archives it to prove no guard refuses.

In that state the roster panel rendered the **active** empty state:

> Nobody on this roster yet. Add students below. They join by typing the class
> code and tapping their own name, so there is nothing else to set up.

On a page that had just removed `AddStudentForm` and replaced the code with
"Inactive". Two sentences, both pointing at things the same page had deliberately
taken away. This is the moment a teacher or a substitute most needs the read-only
state to be coherent — an empty archived class is precisely the one somebody
opens expecting to set it up — and it was the one moment the page contradicted
itself.

Branching that one conditional:

> **No student records to review.** Nobody joined this class before it was
> archived, so there is no roster, no completed work and no evidence here to look
> at. An administrator has to restore the class before anybody can be added to it.

No control named, no code mentioned, the absence of records stated plainly, and
the one route out named. Active + empty is untouched, form and code guidance
included; archived + non-empty is untouched.

## Accessibility

The notice is what a screen-reader user meets instead of the buttons, so its
semantics are part of the correction:

- `<section role="status" aria-labelledby="archived-class-title">` — a standing
  condition the teacher navigated into, not an interruption, and the only status
  region on the page
- its own `<h2>`, so the heading order runs `h1 Room 12` → `h2 This class is
  archived` → `h2 Assigned missions` with no skipped level
- it is placed **before** the panels whose controls are missing, so the
  explanation is read before the absence

Verified in the browser rather than asserted: on the archived page the only
tabbable controls in `<main>` are links — mission titles and "Teach on the board"
— and the roster table contains **zero** buttons. The one `<input>` the sweep
found is the hidden Server Action field in the sign-out form, which is not a tab
stop.

## Known gaps

- ~~`/teacher` still lists an archived class like any other.~~ **This was wrong,
  and backwards.** `listClassesForTeacher` filters `archived_at IS NULL`, so the
  dashboard never listed an archived class at all — the problem was the opposite
  one, that archiving removed the *only* navigation to the read-only page and
  left the records reachable solely from a URL somebody had kept. Corrected in
  the acceptance section below. I wrote that gap without reading the query.
- **The archived notice still says "the roster below" on an empty class.** It
  promises that "every mission each child completed" stays readable, directly
  above "No student records to review". Not contradictory in the way the empty
  state was — the empty state explains it immediately — but it is generic copy
  meeting a specific state, which is the same shape as this finding. Left alone
  deliberately rather than widened into.
- **The dashboard's archived card is a second place that must not grow a
  control.** The page-level list and the test's list now cover two surfaces
  rather than one, with the same weakness named below.
- **Nothing enumerates mutation controls.** The five components are a list in the
  page and a matching list in the test. A sixth added tomorrow would render on an
  archived class and nothing would object until somebody wrote it into both. The
  same shape as the `archived_at` list sprints 76–82 kept getting wrong, one
  layer up.
- **The archived notice is authored prose in a component**, not in the domain
  layer beside `LAPSED_STAFF_BODY` and the rest. Only the title is exported and
  asserted; the three paragraphs are matched by phrase.
- **Screen-reader behaviour is asserted structurally, not heard.** Role, label,
  heading order and tab stops are checked; nothing has been run through an actual
  screen reader.
