# Sprint 56 — the seat count nobody checked

**Date:** 2026-08-28
**Scope:** seat-licence validation. Third and last of the unconstrained-column
family. No schema, no billing, no scope beyond making a bad value safe.

## The finding

`schools.licensed_students` is unconstrained and was trusted as a contract
number everywhere. `licenceStatus` returned the raw value with `Math.max` over
it, and both write paths compared against it as an ordinary limit.

With **`-5`**:

- the buyer saw *"90 of -5 licensed"*;
- teachers were told the school had exceeded a **negative** licence;
- quote messages and audits repeated `-5` back as the current agreement;
- **every** enrolment and restore was misclassified as an overage, so no child
  could be added at all.

With **`5001`** or larger, the repository granted capacity outside the 1–5000
range the product's own quote form accepts, and the buyer UI presented it as
purchased entitlement. SQLite's INTEGER affinity does not prevent a float or
text being stored either.

A classroom blocker and a contract-integrity defect at the same time.

## The rule

`MIN_LICENSED_STUDENTS = 1`, `MAX_LICENSED_STUDENTS = 5000`, and
`isRecognisedSeatCount` requiring a number, an integer, and membership of that
range — **exactly the range `requestPlanChangeAction` already enforced**, now
read from one place by both, so an administrator cannot request a number the
repository would refuse and the repository cannot accept one the form rejects.

Nothing is coerced. No `Number()`, no clamp, no round, no `Math.max` into
validity, no falling back to a plan's suggested seats. **A malformed vendor
value is not evidence of what a school bought.**

## The type does the work

`LicenceStatus` is now discriminated:

```ts
type LicenceStatus =
  | { recognised: true; used: number; licensed: number; remaining: number }
  | { recognised: false; used: number };
```

`used` is always real — counted from rosters, not read from the account. When
the stored number is not a contract value there is simply **no `licensed` and no
`remaining` to display or compare against**. The old shape handed every caller a
number and no way to know it meant nothing; making it unrepresentable surfaced
all eleven consumers at compile time, which is how the two buyer pages were
found rather than remembered.

## Fail closed at both write paths

`createStudent` and `restoreClass` check `status.recognised` **before** the
ordinary capacity comparison and throw `LicenceNotRecognisedError` — distinct
from `LicenceExceededError`, because nothing was exceeded and telling a teacher
otherwise would be false as well as unhelpful. Nothing is written; no class,
child or record is removed, archived or changed.

Valid 1–5000 and legitimate over-cap states behave exactly as before.

## What staff see, and do not

> This school's seat licence needs configuration, so no new students can be
> enrolled. Adding a student has been declined and nothing has been changed —
> every class, roster and record is exactly as it was. Ask Rosa Delgado to have
> the seat licence corrected on the account.

**No digits at all**, asserted by test: the malformed value never reaches a
teacher, and neither does an overage claim. Audited as
`roster.blocked_by_licence_config` and
`class.restore_blocked_by_licence_config` — distinct from the overage actions,
no child named, and **the raw value is not written into the audit trail
either**.

## Buyer surfaces

- **Program status**: *"Student places: 90"* with *"Seat licence needs
  configuration — no new students can be enrolled"*, and the entitlement block
  reading *"Whole school · seat licence needs configuration"*.
- **School overview**: the enrolled count stays real; the hint says the same.
- Existing aggregates and records remain visible throughout.
- **The quote form does not prefill a malformed value** — `defaultValue={seats ??
  undefined}` — because offering it back would let a submitted quote launder it
  into an agreement. A valid desired count is still accepted normally.
- **Quote success and audit copy no longer repeat it**: *"Your seat licence still
  needs configuration, and this request has not changed it."*

## Tests

Nine cases, **all failing against the previous code** when the source is
stashed. A sweep of `-12, -5, 0, 2.5, 5001, 1_000_000, NaN, "30", null,
undefined, {}` for the classifier, and the storable subset — including the text
value `"thirty"` — through the database. They prove: no enrolment, no restore,
no class or child mutation with counts compared table by table, no success
audit, a distinct configuration audit and refusal, the raw value never marketed
as entitlement on either page, and the quote request still usable without
changing the stored value. Boundaries **1 and 5000** are valid and ordinary
over-cap behaviour is unchanged. Drift guards cover the classifier, both
repository paths (configuration checked *before* capacity), both actions and
both buyer pages.

One fixture correction worth noting: `createTestDb` had licensed **100000**
seats since sprint 42 — itself a number no school could buy. It is now 5000, the
real maximum, still far more than any test enrols.

**616 tests, up from 607.**

## Verified in the browser

**`-5` at 1280×800.** School overview: *"90 | Seat licence needs configuration —
no new students can be enrolled"*. Program: *"STUDENT PLACES | 90 | Seat licence
needs configuration…"* and *"Whole school · seat licence needs configuration"*.
**`-5` appears nowhere on either page**, the quote field is **empty**, and
aggregates are intact. A quote for 150 succeeded with *"Your seat licence still
needs configuration, and this request has not changed it"*; the stored value
remained `-5` and the audit read *"Current entitlement unchanged at school, a
seat licence that needs configuration."* Teacher add refused with the message
above — **no digits in it** — and no crash.

**`5001` at 768×1024.** Program and overview both show the configuration state
with **`5001` appearing nowhere**; admin Restore refused with the same message,
class still Archived; no overflow at either size.

**Recovery**: with 120 restored, Program reads *"90 of 120 | 30 left"*, the
entitlement block *"Whole school · 120 licensed students"*, and the quote field
prefills `120`.

Demo restored: plan school, 120 seats, retention 12, four active classes, 90
students, 885 attempts, 16 audit rows.

## Observed, not built

- **The column is still unconstrained.** Safe, visible and recoverable now; not
  prevented. A CHECK constraint needs a migration.
- **This closes the family.** `plan` (53), `retention_months` (54) and now
  `licensed_students`; `benchmark_window` has had a CHECK constraint from the
  start. Every vendor-set column on `schools` has now been either constrained or
  classified — except the date fields, which are validated on write but not read
  defensively.

## The lesson

**Making the invalid state unrepresentable is what found the callers.** The
first two fixes in this family were guards added at the places I could think of.
This one changed the type so a malformed licence has no `licensed` field at all,
and the compiler produced the list — including two buyer pages I would not have
gone looking for, because nothing about "seat validation" suggests the school
overview.

Where a value can be meaningless, the shape that carries it should not pretend
otherwise. A guard protects the paths you remember; a type protects the ones you
do not.
