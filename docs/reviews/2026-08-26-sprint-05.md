# Sprint 05 review — 26 August 2026

**Scope.** A content-only pass across the permission, verification and
tool-choice lessons. The review looked for technically brittle claims that
teach the right instinct through an absolute that is not true of every current
device or AI product.

**Method.** Read all nine mission decision paths, choice feedback, teacher
misconception notes and family follow-ups against `../classroom-review.md`.
Checked the revised permission and tool-choice feedback in the independent
student player at 768×1024, and the revised confidence feedback in Classroom
Mode at 1280×800. The changed screens were also checked for horizontal
overflow, full-viewport fit where expected, focus movement and browser errors.

---

## Findings and what changed

### 1. Permission guidance described one device policy as universal — fixed

The filter mission said that location access tells an app exactly where the
child is all day, even when the app is closed, and that photo access means every
picture on the tablet. Those outcomes are possible, but permission scope varies
by device, operating system and the option selected. A child taught that exact
claim could later see a more limited permission and conclude that the lesson no
longer applies.

The feedback now stays with the observable decision rule:

- Location *can* tell an app where the child is, and a fox filter does not need
  location to add ears.
- Letting the app use old pictures is a real trade, but the live filter only
  needs the camera; camera-only shares less.

This preserves calibrated choice. The lesson does not imply that every
permission request is dangerous or that every device behaves the same way.

### 2. Verification guidance treated all AI products as identical — fixed

The confidence and Four Doors missions used three brittle shortcuts: AI tools
always sound sure, an answer without a named person was never checked, and AI
tools usually do not name sources. These statements overreach and will age
poorly as interfaces change. They also blur the actual skill, which is judging
the evidence available for a specific answer.

The revised progression is now:

1. An AI answer *can* sound sure and still be wrong.
2. Tone is not evidence; look for something that can be checked.
3. If an answer shows no source, the child cannot see or repeat the check.
4. If a tool does name a source, follow it and inspect the source rather than
   treating the citation itself as proof.

Teacher notes and the family activity now accept either a person or an
organisation as the party responsible for a source. This avoids teaching that
an official science or public-agency page is weak merely because it has no
individual byline.

## Content safeguards added

- The standing classroom review now includes **Technical durability**: scope
  claims to what the child can observe and teach rules that survive changes to
  apps, devices and models.
- The reading-load test now checks prompts, choices, feedback headlines,
  feedback bodies and wrap-ups as well as narration. Every student-facing
  sentence remains at or below 32 words.
- A regression check rejects the specific technical overclaims removed in this
  sprint.

## Verification

- **Independent, 768×1024:** revised location feedback and Four Doors source
  feedback render completely, keep the next action obvious and have no
  horizontal overflow (`scrollWidth === 768`). The Four Doors feedback fits in
  one viewport; the permission screen scrolls vertically by only its normal
  page chrome.
- **Classroom Mode, 1280×800:** revised confidence feedback, all choice
  comparison controls and the teacher controls fit in one viewport
  (`scrollWidth === 1280`, `scrollHeight === 800`). Text remains legible from
  the board layout.
- **Browser console:** no errors in the changed flows.
- **Automated checks:** lint, typecheck and all 152 tests pass. The default
  Turbopack production build passed once after the curriculum edits, then later
  final-verification attempts were blocked while its CSS worker tried to bind
  a local port (`EPERM`). A production build with Next's supported webpack
  builder completed successfully, including all 28 routes. This is recorded as
  an environment/builder failure rather than hidden as a pass.
- **Privacy and data:** no field, event, network call or persistence behaviour
  changed. Student input remains authored choices only. Nothing introduces an
  open chatbot.

## Deliberately left

- The product still uses simplified explanations such as a language tool
  choosing likely words. That is an age-appropriate model for grades 2–4 and
  does not change the decision rule; a deeper model-mechanics lesson would add
  abstraction without improving the choice a child makes.
- Mission 6 still treats the school plaque as the closest source for its
  fictional building date. The story immediately confirms it against the
  original office records, so it teaches corroboration rather than blind trust
  in plaques.
- No visual redesign was made. The existing student and classroom layouts
  delivered the revised content without obstruction, so UI work would not have
  improved this sprint's learning goal.
