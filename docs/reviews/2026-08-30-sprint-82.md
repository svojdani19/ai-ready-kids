# Sprint 82 — three reviews said two actions; it was three

**Date:** 2026-08-30
**Reviewed against:** HEAD `b4688ca`
**Scope:** the class-lifecycle check on teacher classroom mutations. One new
module, one resolver signature, five call sites, two message constants derived
rather than written, one test file. No schema change, no new field, no UI
change, nothing student-facing.

## The finding

Sprint 69 made archiving an access boundary **for children**: student sessions
close on the next request, the join code rotates, the cohort leaves the active
seat count. It never became a boundary for staff. `requireOwnActiveClass`
answered ownership and the subscription term and never read `archived_at`, so
every action that cared had to remember to check for itself.

Three sprints then added that check one action at a time, and each wrote down
what was left:

- **Sprint 76** fixed `setAssignmentAction`, and recorded that widening the
  resolver "would change every classroom mutation at once, which is a different
  correction". Named as remaining: **rename, remove, rotate**.
- **Sprint 79** fixed `removeStudentAction`, wrote the same sentence, and named
  as remaining: **rename and rotate**.
- **Sprint 81** listed **rename and rotate** as a known gap for the third time.

All three lists were wrong in the same way. Enumerating the actions in the file
rather than the sentences in the reviews:

| Action | Checked `archived_at` |
| --- | --- |
| `addStudentAction` | **no** |
| `renameStudentAction` | **no** |
| `removeStudentAction` | yes (sprint 79) |
| `rotateJoinCodeAction` | **no** |
| `setAssignmentAction` | yes (sprint 76) |

**`addStudentAction` was never named once**, across three sprints of writing
about this exact problem — and it is the most consequential of the three. It
enrolls a child into a cohort whose year is finished, consumes a licensed seat
against the school's cap, and puts that child on the roster the moment somebody
restores the class. A list maintained by hand is a list that is quietly wrong,
which is the argument against per-action checks in one line.

## The correction

The resolver every classroom mutation already used now answers three questions
instead of two, and the third cannot be skipped:

```ts
async function requireOwnActiveClass(classId: string, operation: ClassOperation) {
  const resolved = await requireOwnClass(classId);
  assertSubscriptionActive(resolved.db, resolved.user.school_id);
  if (resolved.classroom.archived_at) throw new ClassArchivedError(operation);
  return resolved;
}
```

1. **Ownership** — is this the caller's own class? Theirs after the term ends too.
2. **Entitlement** — is the subscription active? Theirs, and still not editable.
3. **Lifecycle** — is the class archived? Theirs, paid for, and parked.

There is no way to resolve a class for a mutation without naming the mutation,
so a new action cannot inherit the check by accident or miss it by omission.

### Why every mutation, checked one verb at a time

Adding, renaming and removing all change what a finished year's roster, exports
and history say. Assigning goes live for children on restore. **Rotating is the
only arguable one** — archiving already rotated the code and signed the room out,
so a second rotation changes a credential nobody can use. It is refused anyway,
because its audit entry claims the old code "is now rejected on its next use, for
new joins and for browsers already signed in with it", and on a parked class
there are no joins and nobody signed in. A true record of a pointless act is
still a false sentence.

Restore, delete and retention stay outside: they are administrator operations on
the class as an object, and they are how a parked class stops being parked.
Gating them here would make archiving a trap.

### The refusal still says which thing it is refusing

A single generic message would have been less code and a worse product — it
leaves a teacher to work out which of the things they just tried is being
refused. `CLASS_OPERATIONS` maps each operation to the end of the sentence
"Restore the class before ___":

| Operation | Refusal |
| --- | --- |
| `add_student` | …before adding a student to it. |
| `rename_student` | …before renaming a student on it. |
| `remove_student` | …before removing a student from it. |
| `rotate_code` | …before giving it a new class code. |
| `set_assignment` | …before changing its missions. |

`ASSIGNMENT_CLASS_ARCHIVED` and `REMOVE_STUDENT_CLASS_ARCHIVED` are now derived
from that map rather than written out, so the two that existed cannot drift from
the three that did not. The assignment message gained two words in the process —
"Restore **the class** before changing its missions" — which is the map's
phrasing and is what makes all five one sentence with one variable.

`ClassArchivedError` throws, matching `SubscriptionLapsedError`, and
`asExpectedError` converts it to the `{ error }` an action renders. A caller that
forgets that conversion fails loudly rather than writing, which is the same
backstop the subscription gate has had since sprint 49.

### Order matters, deliberately

Entitlement is answered **before** lifecycle. A lapsed school's archived class is
refused by both rules, and the subscription answer is the more useful one: it
explains why every other class in the building is refusing too, and it is the one
a teacher can act on. "That class is archived" would send them to restore a class
that would still refuse.

## Acceptance evidence

`tests/class-lifecycle-gate.test.ts`, 19 tests, every one through the **real
exported Server Action** with a real signed teacher session — nothing reaches
into the resolver, because the claim is about what an action does.

| Test | Proves |
| --- | --- |
| five refusals | each action returns its own sentence, no `ok`, and the classes, students, attempts, benchmarks, assignments **and audit log** are byte-identical: a refusal is not an event |
| five restores | after `restoreClass` the lifecycle refusal is gone and `archived_at` is null |
| above the transaction | with an `ABORT` trigger **armed on `audit_log`**, all five still return the archived message — proving none reached its transaction or took a write lock |
| distinct sentences | all five differ, and all match one shape |
| map coverage | every operation named in an action exists in the map **and** every operation in the map is used by an action, so a stale phrase cannot sit there looking like coverage |
| entitlement first | a lapsed school gets `LAPSED_WRITE_REFUSAL` from all five, an unreadable term gets `UNVERIFIED_WRITE_REFUSAL`, and fixing the term falls through to the class |
| one place | `archived_at` appears exactly **once** in `teacher.ts`, inside the resolver — a per-action check is now a duplicate, and a duplicate is how the answer gets overridden with a different sentence |
| no bypass | every exported action that handles a `classId` resolves through `requireOwnActiveClass`, `createClassAction` excepted because it has no class yet |
| no unnamed call | every call site passes an operation |

**Mutation-checked four ways, one at a time:**

| Mutation | Result |
| --- | --- |
| remove the check from the resolver | 13 fail — all five refusals, all five restores, the transaction probe, the fall-through, and the one-place assertion |

| one action passes the wrong operation | 5 fail, naming that action |
| add a new class-holding action that skips the resolver | 1 fails, naming the function |

`archiveClass`, deliberately: `archiveClass` also rotates the join code, and a
rotation cannot be undone to the original value. One column, exactly reversible.

**1280×800.** Signed in as the class's own teacher, three refusals were produced
through the real controls and all three rendered on the page at once:

> That class is archived. Restore the class before changing its missions.
> That class is archived. Restore the class before adding a student to it.

**768×1024.** The assignment refusal renders at 352px inside a 768px viewport,
`overflow: false`.

**Recovery.** With `archived_at` back to null, the assignment toggle moved 21 → 20
→ 21 with no refusal at any point.

Screenshots of the message could not be captured: the Browser pane was hidden for
this pass and painted blank, as it did in sprint 81's acceptance correction. The
evidence above is rendered text and geometry read from the live page at each
emulated viewport — not pixels I did not see.

### What the class page does not do, which this sprint did not fix

An archived class renders **exactly like an active one**. There is no badge, no
banner, nothing marks it as parked, and the assignment panel still says "Turn a
mission on and it appears on every student's map in this class straight away" —
which is now false for this class. Every control is live and every one refuses.

The refusals are correct and specific, so nothing is lost or misleading after the
fact. But a teacher learns the class is parked by being refused, which is not the
standard the rest of this product holds itself to. It is a UI correction rather
than an access one, it is out of scope here, and it is the first known gap below.

## Known gaps

- **An archived class looks active.** No badge, no banner, and an assignment
  panel that still promises children see the change "straight away". The
  refusals are correct; the page gives no warning before them.
- **`getClass` still hands out archived classes.** The resolver reads
  `archived_at` after the fact rather than the repository refusing to resolve one
  for a mutation. That is the next layer down, and it would catch a caller that
  never goes through `requireOwnActiveClass` at all.
- **The no-bypass test keys on the string `classId`.** An action that named the
  parameter something else would not be enumerated. It is a heuristic over one
  file, not a type.
- **Administrator class operations are unexamined here.** Archive, restore,
  delete and retention are deliberately outside this gate; whether each is
  correct about a parked class was reasoned about, not tested, in this sprint.
